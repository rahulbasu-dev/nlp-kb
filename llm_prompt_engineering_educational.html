Introduction to LLMs & Prompt Engineering

Large Language Models have revolutionized AI, transforming how we interact with computers through natural language. Learn to harness their power through effective prompt engineering.

From GPT to Claude: The Era of Foundation Models

🤖 Introduction to Large Language Models

Understanding what LLMs are and why they matter

Introduction to Large Language Models

📚 The Well-Read Student Analogy

Think of an LLM as an incredibly well-read student who has read billions of pages from books, websites, and documents. When you ask a question, this student draws on patterns they've seen across all that text to generate a thoughtful response. They haven't memorized everything, but they've learned deep patterns about how language works and how concepts relate to each other.

A Language Model is a system that predicts the probability of sequences of words (or tokens). At its core, it answers: "What word comes next?"

Traditional language models (like N-grams) used simple statistical patterns. Modern Large Language Models (LLMs) use neural networks with billions of parameters trained on massive text corpora, enabling them to understand context, generate coherent text, reason about problems, and even write code.

Scale Changed Everything

The progression of model scale has been dramatic:

  • GPT-1 (2018): 117 million parameters
  • GPT-2 (2019): 1.5 billion parameters
  • GPT-3 (2020): 175 billion parameters
  • GPT-4 (2023): ~1.7 trillion parameters (estimated)

As models grew, they exhibited emergent abilities—capabilities that appeared suddenly at scale, like few-shot learning, chain-of-thought reasoning, and complex instruction following.

Transformer Architecture

Modern LLMs are built on the Transformer architecture (Vaswani et al., 2017), which uses self-attention mechanisms to process sequences in parallel and capture long-range dependencies.

Self-Attention Mechanism
\[ \text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V \]

Where Q (queries), K (keys), and V (values) are learned projections of the input. The attention mechanism allows each token to "look at" all other tokens and weigh their importance, with scaling factor \(\sqrt{d_k}\) for numerical stability.

Tokenization

LLMs don't process words directly—they break text into tokens (subword units) using algorithms like Byte-Pair Encoding (BPE).

📝 BPE Tokenization Example

Input: "unhappiness"

Tokens: ["un", "happi", "ness"]

Common words are single tokens (e.g., "the"), while rare words split into subwords. This balances vocabulary size with coverage.

Temperature & Sampling

LLMs generate text by sampling from a probability distribution over tokens. The temperature parameter controls randomness:

Temperature Scaling
\[ P(x_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)} \]

T = 0: Greedy (always pick highest probability)
T = 1: Standard softmax distribution
T > 1: More random, creative output
T < 1: More focused, deterministic output

Sampling strategies:

  • Top-k: Sample from the k most likely tokens
  • Top-p (nucleus sampling): Sample from the smallest set of tokens whose cumulative probability exceeds p

⚠️ Hallucination Warning

LLMs can hallucinate—they generate plausible-sounding but factually incorrect text. This happens because they're trained to predict likely continuations, not to verify truth. Always verify critical information from reliable sources.

⚙️ How LLMs Work

The training pipeline from raw text to helpful assistant

The Training Pipeline

Modern LLMs are created through a three-stage process:

1. Pre-training: Learning Language

Models are trained on massive text corpora (books, websites, code) to predict the next token. This is self-supervised learning—no human labels needed, just raw text.

Pre-training Loss (Causal Language Modeling)
\[ \mathcal{L} = -\sum_{i=1}^{N} \log P(w_i | w_1, w_2, \ldots, w_{i-1}) \]

The model learns to minimize the negative log-likelihood of predicting each token given all previous tokens. This simple objective results in rich language understanding.

2. Fine-tuning: Domain Specialization

The pre-trained model is further trained on domain-specific data (e.g., medical texts, legal documents, or instruction-response pairs) with supervised learning.

Fine-tuning Objective
\[ \mathcal{L}_{\text{FT}} = -\sum_{(x, y) \in \mathcal{D}} \log P(y | x) \]

Where \(\mathcal{D}\) is a dataset of (input, output) pairs. The model learns to generate desired outputs given specific inputs.

3. RLHF: Alignment with Human Preferences

Reinforcement Learning from Human Feedback (RLHF) trains the model to produce outputs humans prefer—helpful, honest, and harmless responses.

RLHF: Reward Model
\[ R(x, y) = \text{Reward Model Score} \]

Humans rank model outputs (A vs B). A reward model learns to predict these preferences. The LLM is then optimized (using algorithms like PPO—Proximal Policy Optimization) to maximize reward while staying close to the original model.

🌟 Emergent Abilities

Emergent abilities are capabilities that appear suddenly at scale, not present in smaller models:

  • Few-shot learning: Learn new tasks from just a few examples in the prompt
  • Chain-of-thought reasoning: Break down complex problems step-by-step
  • Code generation: Write functional programs in multiple languages
  • Theory of mind: Reason about beliefs and intentions of others

In-Context Learning

One of the most remarkable properties of LLMs is in-context learning: they can learn new tasks from examples provided in the prompt, without any weight updates.

Unlike traditional machine learning (which requires training on labeled data), LLMs perform "learning" at inference time by recognizing patterns in the prompt.

📝 In-Context Learning Example

Prompt:

Translate English to French:
hello → bonjour
goodbye → au revoir
thank you → merci
good morning →

Model Output: "bon matin" or "bonjour"

The model recognizes the translation pattern and applies it to the new example, without being explicitly trained on translation.

✏️ Try It Yourself!

Given the pre-training objective (predict next token), why might LLMs be good at text completion but struggle with factual accuracy?

Solution:

LLMs are optimized to predict likely continuations based on patterns in training data, not to verify factual truth. A sentence can be grammatically perfect and contextually plausible (high probability) but factually wrong. The model lacks a "truth verification" mechanism—it doesn't have access to a knowledge base or the ability to check facts. This is why hallucinations occur: the model generates fluent, coherent text that sounds right but may be incorrect.

🎯 Prompt Engineering Fundamentals

The art and science of communicating with LLMs

Prompt Engineering Fundamentals

👨‍💼 The Literal-Minded Assistant Analogy

Prompt engineering is like giving instructions to a brilliant but literal-minded assistant. If you say "tell me about dogs," they might give a brief, generic answer. But if you say "as a veterinary expert, provide a detailed explanation of dog breeds, their health characteristics, and care requirements, formatted as a markdown table," you'll get exactly what you need. Clarity and specificity unlock the model's full potential.

Core Principles of Effective Prompting

1. Be Specific

Vague prompts yield vague answers. Specific prompts yield targeted, useful responses.

❌ Bad Prompt

"Tell me about dogs."

Too vague. The model doesn't know what aspect of dogs you want to know about or how detailed the answer should be.

✅ Good Prompt

"Explain the differences between working dog breeds (German Shepherds, Border Collies, Labrador Retrievers) in terms of temperament, exercise needs, and ideal living environments. Use bullet points."

Specific topic, clear scope, defined output format.

2. Provide Context

Give the model context about the task, your goals, and the desired perspective.

📝 System Prompts & Role Assignment

System Prompt: "You are an expert marine biologist with 20 years of experience studying coral reef ecosystems."

User Prompt: "Explain why coral reefs are important and how climate change affects them."

The system prompt sets the "role" and expertise level, leading to more authoritative, detailed responses.

3. Structure Your Output

Specify the format you want: JSON, markdown, tables, bullet points, step-by-step instructions, etc.

📝 Output Format Specification

Prompt: "List the top 5 programming languages for web development. For each, provide: name, primary use case, difficulty level (1-5), and a one-sentence description. Format as JSON."

Expected Output:

[
  {
    "name": "JavaScript",
    "use_case": "Frontend & backend development",
    "difficulty": 3,
    "description": "The essential language for web interactivity."
  },
  ...
]

4. Use Delimiters

Separate different parts of your prompt with clear delimiters: triple backticks, XML tags, section headers, etc.

Prompt Anatomy Example

[System Message]
You are a helpful coding assistant.
[Context/Examples]
Here's an example of the code style I prefer: <example>...</example>
[User Query]
Write a Python function to calculate Fibonacci numbers.
[Output Format]
Provide the code in a ```python code block with comments.

🎓 N-shot Prompting

Teaching by example: zero-shot, one-shot, and few-shot learning

N-shot Prompting

N-shot prompting refers to providing N examples of a task in the prompt before asking the model to perform the task. It's a spectrum:

Zero-shot: No Examples

The model relies entirely on its pre-trained knowledge. Modern LLMs are surprisingly capable at zero-shot tasks.

Zero-shot Probability
\[ P(\text{output} | \text{instruction}) \]

The model generates output based solely on the instruction, without examples.

📝 Zero-shot Example: Sentiment Analysis

Prompt:

Classify the sentiment of this review as Positive, Negative, or Neutral:
"This product exceeded my expectations!"

Sentiment:

Model Output: "Positive"

One-shot: Single Example

Provide one demonstration of the task to guide the model.

📝 One-shot Example: Sentiment Analysis

Prompt:

Classify sentiment as Positive, Negative, or Neutral:

Review: "Terrible quality, broke after one day."
Sentiment: Negative

Review: "This product exceeded my expectations!"
Sentiment:

Model Output: "Positive"

Few-shot: Multiple Examples

Provide several examples (typically 3-5) to establish a clear pattern.

📝 Few-shot Example: Sentiment Analysis

Prompt:

Classify sentiment as Positive, Negative, or Neutral:

Review: "Amazing! Best purchase ever."
Sentiment: Positive

Review: "Terrible quality, broke after one day."
Sentiment: Negative

Review: "It's okay, nothing special."
Sentiment: Neutral

Review: "Love it! Highly recommend."
Sentiment: Positive

Review: "Not bad, but not great either."
Sentiment:

Model Output: "Neutral"

Method # Examples When to Use Pros Cons
Zero-shot 0 Simple, well-known tasks Fast, no examples needed May misunderstand task
One-shot 1 Clear task with specific format Minimal context, quick May not capture full pattern
Few-shot 3-5 Complex or ambiguous tasks Clear pattern, high accuracy Uses more tokens, longer prompt

🧠 How In-Context Learning Works

Few-shot prompting works because LLMs perform in-context learning—they recognize patterns from examples without updating weights. The model's attention mechanism allows it to "look back" at the examples and apply the same pattern to the new input. This is a form of meta-learning: the model has learned how to learn from examples during pre-training.

Best Practices for Few-shot Prompting

  • Diverse examples: Cover different edge cases and variations
  • Consistent format: Use the same structure for all examples
  • Order matters: Recent examples have more influence (recency bias)
  • Label balance: Include examples from all classes (for classification tasks)

🔗 Chain-of-Thought Prompting

Unlocking reasoning by asking models to think step-by-step

Chain-of-Thought Prompting

📓 The Math Student Analogy

Like asking a math student to "show your work" instead of just writing the final answer. When the model generates intermediate reasoning steps, it's more likely to arrive at the correct answer—and you can verify the logic. Without chain-of-thought, the model might jump to conclusions or make errors in complex reasoning.

Chain-of-Thought (CoT) prompting encourages the model to break down complex problems into intermediate reasoning steps before providing the final answer.

Standard CoT: Providing Reasoning Examples

📝 Without CoT (Direct Answer)

Prompt:

Q: If a store has 23 apples and sells 14, then receives a shipment of 30 apples, how many does it have?
A:

Model Output: "39" (Incorrect! 23 - 14 + 30 = 39, but common error is 23 + 30 - 14 = 39)

📝 With CoT (Step-by-Step Reasoning)

Prompt:

Q: If a store has 23 apples and sells 14, then receives a shipment of 30 apples, how many does it have?
A: Let's think step by step.
- The store starts with 23 apples
- They sell 14 apples: 23 - 14 = 9 apples remaining
- They receive 30 more apples: 9 + 30 = 39 apples
Therefore, the store has 39 apples.

Model Output: (Follows the reasoning pattern correctly)

Zero-shot CoT: Just Add "Let's think step by step"

Surprisingly, simply appending "Let's think step by step" to a prompt can dramatically improve reasoning performance—no examples needed!

📝 Zero-shot CoT Example

Prompt:

Q: If a train travels 120 km in 2 hours, what is its speed in meters per second?

Let's think step by step.

Model Output:

Step 1: Calculate speed in km/h: 120 km ÷ 2 hours = 60 km/h
Step 2: Convert to m/s: 60 km/h × (1000 m / 1 km) × (1 h / 3600 s) = 16.67 m/s
Therefore, the speed is approximately 16.67 m/s.

Self-Consistency: Majority Voting

Generate multiple reasoning paths with CoT, then take the majority vote on the final answer. This reduces the impact of any single reasoning error.

Self-Consistency Voting
\[ \text{answer} = \arg\max_{a} \sum_{i=1}^{n} \mathbb{1}[\text{path}_i \to a] \]

Generate n reasoning paths (e.g., n=5), extract the final answer from each, and select the most common answer. Works best with temperature > 0 to get diverse reasoning paths.

Tree of Thoughts: Exploring Multiple Branches

Tree of Thoughts (ToT) explores multiple reasoning branches at each step, evaluating which paths look most promising.

Tree of Thoughts Example

Initial Problem
Approach A
Approach B
Approach C
A1 → Solution
A2 → Dead end
B1 → Solution

The model explores multiple reasoning paths and can backtrack if a path doesn't look promising.

Task Standard Zero-shot CoT Few-shot CoT Self-Consistency
Arithmetic35%68%78%85%
Commonsense Reasoning52%71%79%83%
Symbolic Reasoning28%55%72%80%

⚠️ Cost and Latency Tradeoff

CoT prompting increases the number of generated tokens (reasoning steps), which means:

  • Higher latency: More tokens take longer to generate
  • Higher cost: API pricing is per token

Use CoT strategically for complex reasoning tasks, not for simple lookups or factual questions.

✏️ Try It Yourself!

Use CoT to solve: "A store had 42 apples. They sold 15 in the morning and received a new shipment of 28. How many do they have now?"

Solution with Chain-of-Thought:

Let's think step by step:
1. The store starts with 42 apples
2. They sell 15 apples in the morning: 42 - 15 = 27 apples
3. They receive a shipment of 28 apples: 27 + 28 = 55 apples

Therefore, the store now has 55 apples.

💡 Generated Knowledge Prompting

Generate relevant knowledge first, then use it to answer

Generated Knowledge Prompting

Generated Knowledge Prompting is a two-step technique: first, ask the model to generate relevant facts or knowledge about a topic, then use that knowledge to answer the question.

Two-Step Process

Step 1: Generate Knowledge
"Generate 5 important facts about [topic]"
→ Model outputs facts
↓
Step 2: Answer Using Knowledge
"Using these facts: [facts], answer: [question]"
→ Model outputs comprehensive answer

Concrete Example: "Is a penguin a bird?"

📝 Without Generated Knowledge

Prompt: "Is a penguin a bird?"

Model Output: "Yes, a penguin is a bird."

Brief and correct, but lacks explanation.

📝 With Generated Knowledge

Step 1 Prompt: "Generate 5 facts about penguins."

Model Output (Facts):

  • Penguins are flightless birds that belong to the family Spheniscidae.
  • They are found almost exclusively in the Southern Hemisphere.
  • Penguins have adapted to aquatic life with flipper-like wings for swimming.
  • They lay eggs and are warm-blooded vertebrates.
  • Penguins have feathers, beaks, and skeletons characteristic of birds.

Step 2 Prompt: "Using these facts: [above facts], answer: Is a penguin a bird?"

Model Output:

Yes, a penguin is definitively a bird. Despite being flightless, penguins belong to the family Spheniscidae and possess all the key characteristics of birds: they are warm-blooded vertebrates, have feathers and beaks, lay eggs, and have a skeletal structure typical of the avian class. Their wings have evolved into flippers for swimming, an adaptation to their aquatic lifestyle, but this doesn't change their classification as birds.

Comprehensive, well-reasoned answer with supporting evidence.

Knowledge-Conditioned Probability
\[ P(\text{answer} | \text{question}, \text{knowledge}) > P(\text{answer} | \text{question}) \]

When relevant knowledge is provided, the model can generate better answers. The knowledge acts as "context retrieval" performed by the model itself.

When to Use Generated Knowledge Prompting

  • Knowledge-intensive QA: Questions requiring specific facts or domain knowledge
  • Fact verification: "Is X true?" tasks benefit from generating supporting/refuting evidence first
  • Complex reasoning: Generate relevant principles or rules before applying them

🔍 Comparison with RAG

Generated Knowledge uses the LLM itself as the knowledge base. Retrieval-Augmented Generation (RAG) retrieves knowledge from an external database (e.g., vector search over documents).

  • Generated Knowledge: Fast, no external data needed, but limited by model's pre-training
  • RAG: Can access up-to-date or proprietary information, but requires infrastructure

Both techniques share the same goal: provide relevant context before answering.

✏️ Try It Yourself!

Use generated knowledge prompting to answer: "Can sound travel through space?"

Solution:

Step 1: "Generate 5 facts about sound and space."

Generated Facts:

  • Sound requires a medium (solid, liquid, or gas) to travel through.
  • Sound waves are vibrations of molecules in a medium.
  • Space is a near-perfect vacuum with extremely low density of particles.
  • In vacuum, there are insufficient molecules for sound waves to propagate.
  • Astronauts use radio waves (electromagnetic) to communicate, not sound.

Step 2: "Using these facts, answer: Can sound travel through space?"

Answer: "No, sound cannot travel through space. Sound waves require a medium of molecules to propagate, but space is a near-perfect vacuum with insufficient particle density. This is why astronauts rely on radio waves for communication, as electromagnetic waves don't require a medium."

"""
Prompt Engineering Toolkit
===========================
Complete implementation of prompting strategies for LLMs.
"""

from typing import List, Dict, Optional
import json

# Note: Replace with your preferred LLM API (OpenAI, Anthropic, etc.)
from openai import OpenAI

class PromptEngineer:
    """A toolkit for building and testing different prompting strategies."""

    def __init__(self, model: str = "gpt-4", temperature: float = 0.7):
        """
        Args:
            model: LLM model identifier
            temperature: Sampling temperature (0.0-2.0)
        """
        self.client = OpenAI()
        self.model = model
        self.temperature = temperature

    def _call_llm(self, messages: List[Dict[str, str]]) -> str:
        """Call the LLM API with messages."""
        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            temperature=self.temperature
        )
        return response.choices[0].message.content

    def zero_shot(self, task: str, system_prompt: Optional[str] = None) -> str:
        """
        Zero-shot prompting: task with no examples.

        Args:
            task: The task description or question
            system_prompt: Optional system message for context

        Returns:
            Model's response
        """
        messages = []
        if system_prompt:
            messages.append({"role": "system", "content": system_prompt})
        messages.append({"role": "user", "content": task})
        return self._call_llm(messages)

    def few_shot(self, task: str, examples: List[Dict[str, str]],
                 system_prompt: Optional[str] = None) -> str:
        """
        Few-shot prompting: provide examples before the task.

        Args:
            task: The task to perform
            examples: List of {"input": ..., "output": ...} examples
            system_prompt: Optional system message

        Returns:
            Model's response
        """
        # Build few-shot prompt
        prompt = ""
        for ex in examples:
            prompt += f"Input: {ex['input']}\nOutput: {ex['output']}\n\n"
        prompt += f"Input: {task}\nOutput:"

        messages = []
        if system_prompt:
            messages.append({"role": "system", "content": system_prompt})
        messages.append({"role": "user", "content": prompt})
        return self._call_llm(messages)

    def chain_of_thought(self, task: str, examples: Optional[List[Dict]] = None,
                         zero_shot: bool = True) -> str:
        """
        Chain-of-Thought prompting: encourage step-by-step reasoning.

        Args:
            task: The reasoning task
            examples: Optional few-shot examples with reasoning
            zero_shot: If True, use "Let's think step by step"

        Returns:
            Model's response with reasoning
        """
        if zero_shot:
            # Zero-shot CoT: just append the magic phrase
            prompt = f"{task}\n\nLet's think step by step."
            messages = [{"role": "user", "content": prompt}]
            return self._call_llm(messages)
        else:
            # Few-shot CoT: provide examples with reasoning
            prompt = ""
            for ex in examples:
                prompt += f"Q: {ex['question']}\n"
                prompt += f"A: {ex['reasoning']}\n"
                prompt += f"Therefore, the answer is {ex['answer']}.\n\n"
            prompt += f"Q: {task}\nA:"
            messages = [{"role": "user", "content": prompt}]
            return self._call_llm(messages)

    def self_consistency(self, task: str, n_paths: int = 5) -> str:
        """
        Self-consistency: generate multiple reasoning paths and vote.

        Args:
            task: The reasoning task
            n_paths: Number of reasoning paths to generate

        Returns:
            Most common answer across paths
        """
        # Generate multiple CoT responses
        responses = []
        for _ in range(n_paths):
            response = self.chain_of_thought(task, zero_shot=True)
            responses.append(response)

        # Extract final answers (simple heuristic: last line)
        answers = [r.strip().split('\n')[-1] for r in responses]

        # Majority vote
        from collections import Counter
        most_common = Counter(answers).most_common(1)[0][0]

        return f"After {n_paths} reasoning paths, the consensus answer is:\n{most_common}"

    def generated_knowledge(self, question: str, n_facts: int = 5) -> str:
        """
        Generated Knowledge prompting: generate knowledge, then answer.

        Args:
            question: The question to answer
            n_facts: Number of facts to generate

        Returns:
            Answer based on generated knowledge
        """
        # Step 1: Generate knowledge
        knowledge_prompt = f"Generate {n_facts} important facts relevant to answering this question: {question}"
        knowledge = self.zero_shot(knowledge_prompt)

        # Step 2: Answer using knowledge
        answer_prompt = f"Using these facts:\n{knowledge}\n\nAnswer the following question: {question}"
        answer = self.zero_shot(answer_prompt)

        return f"Generated Knowledge:\n{knowledge}\n\nAnswer:\n{answer}"


class PromptTemplate:
    """Reusable prompt templates with variable substitution."""

    def __init__(self, template: str, variables: List[str]):
        """
        Args:
            template: Prompt template with {variable} placeholders
            variables: List of variable names that must be provided
        """
        self.template = template
        self.variables = variables

    def format(self, **kwargs) -> str:
        """
        Format the template with provided variables.

        Args:
            **kwargs: Variable values

        Returns:
            Formatted prompt
        """
        missing = [v for v in self.variables if v not in kwargs]
        if missing:
            raise ValueError(f"Missing variables: {missing}")
        return self.template.format(**kwargs)

    def validate(self) -> Dict[str, bool]:
        """Validate that template has all required placeholders."""
        return {
            "has_system_prompt": "system" in self.template.lower(),
            "has_examples": "example" in self.template.lower(),
            "has_output_format": "format" in self.template.lower(),
            "variables_defined": len(self.variables) > 0
        }

if __name__ == "__main__":
    engineer = PromptEngineer(model="gpt-4", temperature=0.7)

    print("=== Zero-shot Example ===")
    result = engineer.zero_shot("Classify this review as positive or negative: 'Great movie!'")
    print(result)

    print("\n=== Few-shot Example ===")
    examples = [
        {"input": "I love this!", "output": "Positive"},
        {"input": "Terrible product.", "output": "Negative"},
        {"input": "It's okay.", "output": "Neutral"}
    ]
    result = engineer.few_shot("Classify: 'Best purchase ever!'", examples)
    print(result)

    print("\n=== Chain-of-Thought Example ===")
    result = engineer.chain_of_thought(
        "If a train travels 120km in 2 hours, what is its speed in m/s?"
    )
    print(result)

    print("\n=== Generated Knowledge Example ===")
    result = engineer.generated_knowledge(
        "Why do leaves change color in autumn?"
    )
    print(result)

    print("\n=== Prompt Template Example ===")
    template = PromptTemplate(
        template="You are a {role}. {task}\n\nProvide your answer in {format} format.",
        variables=["role", "task", "format"]
    )
    prompt = template.format(
        role="data scientist",
        task="Explain what a p-value is",
        format="markdown"
    )
    print(prompt)
